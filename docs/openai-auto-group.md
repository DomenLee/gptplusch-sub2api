# GPT 账号自动分组

入口：**系统设置 → 网关服务 → GPT 账号自动分组**，位于 429 限流回避配置之后。

## 配置

| 配置 | 默认值 | 范围／行为 |
| --- | --- | --- |
| 新账号默认绑定高倍率分组 | 关闭 | 新建／导入未指定分组时，绑定有效且与账号类型兼容的 OpenAI `>2x` 分组 |
| 异常自动降组 | 关闭 | 独立启用，不改变原有限流和过载冷却策略 |
| 统计窗口 | 5 分钟 | 1–60 的整数，使用滚动时间窗口 |
| 触发次数 | 3 次 | 1–1000 的整数，按账号累计不同请求 |

分组只按基础字段 `rate_multiplier` 判定：`>2` 为高倍率，`<=2` 为低倍率。名称、高峰加价、账号自身倍率和用户折扣不参与判断；“自用”“不降智”等名称没有例外。

保存配置会生成新的计数版本，重新累计失败。当前实例立即更新，其他实例最多在 5 秒内读取新配置。

## 新账号

- 创建弹窗默认勾选有效且兼容的高倍率分组，管理员修改选择后不再自动覆盖。
- 后端创建服务同样处理默认分组，覆盖页面创建、批量创建和 Codex 导入；明确传入非空分组时沿用管理员选择。
- 支持 `skip_default_group_bind` 的导入接口仍可显式跳过默认分组。
- 不修改已有账号、复制账号的显式分组或 Spark 影子账号的继承规则。
- 开启默认高倍率绑定但没有兼容高倍率分组时，创建失败并要求手动选组或关闭该配置，不静默落入低倍率组。

## 异常降组

仅统计实际在高倍率 OpenAI 分组执行的请求：

- HTTP 429 限流。
- HTTP 503／529 且结构化错误或明确文案表明服务器过载，例如 `server_is_overloaded`。
- HTTP 200 的 SSE／WebSocket 失败事件，按其语义状态识别。

普通 503、泛化处理错误、401／403 和网络超时不计入。相同请求在相同账号上的重试、重复终止事件只计一次；WebSocket 按 turn 区分。Redis 共享计数，多实例共同累计。

达到阈值后，在数据库事务中重新检查当前绑定：移除全部 OpenAI `>2x` 分组，并添加所有有效且兼容的 `<=2x` 实体分组。虚拟自动路由入口、已停用／删除分组，以及 API Key 账号不兼容的 OAuth-only 分组不会作为目标。非 OpenAI 分组绑定不变。

没有合法低倍率目标时，保留原绑定。数据库或 Redis 失败不会禁用账号，也不会清空绑定。降组不绕过已有冷却，不自动升回高倍率。管理员可在账号编辑页手动调整。

## 状态与排查

- 成功后，账号状态显示“已自动降至 ≤2x”。
- 失败后，账号管理页顶部固定区域显示具体账号名称、ID、失败原因和“处理分组”入口；账号行也显示失败提示。
- 状态随账号列表刷新更新；可使用现有自动刷新功能。
- 运行记录存于账号 `extra.openai_auto_group_state`，包括时间、状态码、窗口、计数，以及成功时的前后分组 ID。服务器日志事件为 `openai_auto_group_downgraded` 或 `openai_auto_group_failed`。
- 数据库本身不可用时，状态可能无法持久化，需要检查服务器的 `openai_auto_group_status_save_failed` 日志。

管理 API：`GET /api/v1/admin/settings/openai-auto-group` 和 `PUT /api/v1/admin/settings/openai-auto-group`，使用现有管理员认证。

```json
{
  "default_high_rate": false,
  "enabled": false,
  "window_minutes": 5,
  "failure_threshold": 3
}
```
