# GPT 账号自动分组

入口：**系统设置 → 网关服务 → GPT 账号自动分组**，管理 API 继续使用 `GET/PUT /api/v1/admin/settings/openai-auto-group`。

## 规则与默认配置

| 配置 | 默认值 | 行为 |
| --- | --- | --- |
| 跳过分组 | 空列表 | 可多选；绑定任一跳过分组的账号不参与自动升降组，所选分组不作为自动目标 |
| 新账号默认高倍率 | 关闭 | 未指定分组时，绑定有效兼容的 OpenAI >2x 实体组 |
| 异常自动降组 | 关闭 | 最近最多 20 笔账号请求，3 笔出现 429／明确容量过载 |
| 持续慢自动降组 | 关闭 | 最近最多 10 笔同类有效请求，3 笔决策首字 >10 秒 |
| 自动恢复 | 关闭 | 同类成功样本至少 30 笔，最近 30 笔中至少 90% <10 秒，中位数 ≤8 秒，最近 10 笔全部 <10 秒，且不满足慢请求降组条件 |
| 变组保护 | 30 分钟 | 升降组后继续采样，期间不再次变组；可设 0 关闭 |
| 仅观察 | 关闭 | 对所有已启用的规则仅记录建议，不实际搬组；新账号默认分组独立 |

异常或持续慢任一达标可降组，不必等满窗口。每笔请求触发判断，并检查已观测的所有同类窗口，没有统计时间窗口和周期扫描；保护期到期本身不触发动作，由下一笔请求重新判断。首字恰好 10 秒既不算慢，也不算恢复达标的快请求。

`rate_multiplier >2` 为高倍率，`<=2` 为低倍率。名称、高峰加价、账号自身倍率和用户折扣不参与判断。

“跳过分组”按分组 ID 保存。由于升降组以整账号执行，即使请求使用的是其他普通分组，只要该账号同时绑定了跳过分组，也不会自动搬组。已降组账号的原恢复目标被加入跳过列表时，自动恢复同样暂停；取消跳过并保存后重新累计样本，已有变组保护和人工暂停状态保留。

跳过列表同时作用于新账号默认高倍率绑定，管理员显式指定分组仍然有效。降组会过滤被跳过的低倍率目标，过滤后没有合法目标则保留原绑定并提示处理。停用分组可被选择；已删除或不可见的已选 ID 会保留并明确标记，分组列表加载失败不会清空配置。

## 请求与首字口径

- 异常窗口包含实际接入的成功及上游错误请求，成功请求会挤出旧异常；只有 HTTP 429、明确容量过载的 503／529（包括 SSE／WS 失败帧）计为降组异常。普通 503、401／403 等上游错误不算过载。
- 相同请求在相同账号上的重试、重复失败事件只算一次；WS 按 turn。泛化错误后重试出现过载，会升级该笔的异常标记；最终成功不能抹掉先前异常。高倍率账号最终成功后仍记录该请求累计首字，每个请求最多一个延迟样本；经历异常的请求不能计入恢复样本。
- 延迟只使用有有效首字、成功结束的流式结果。失败、取消、无首字和非流式结果不作为快速成功样本。
- 决策首字在现有首字值上累加同账号前序转发尝试及连续重试等待，不把其他账号的耗时记给最终账号，也不改变使用记录展示的首字字段。网关接入前鉴权、并发排队不纳入。
- 同类请求按实际上游模型、有效推理强度、总输入上下文档位（≤32k、32k–128k、>128k、未知）及服务档位区分。上游原始输入 token 包含缓存 token；未知值单独归类。
- 统计按同类请求，执行仍按整账号变组，因此会影响该账号其他模型。

## 降组与恢复

降组事务保存原绑定和每个绑定的优先级，移除全部 OpenAI >2x 绑定，加入所有有效、兼容的 ≤2x 实体组。保留原有低倍率及非 OpenAI 绑定；排除虚拟自动路由入口、停用／删除组和 API Key 不兼容的 OAuth-only 组。没有合法低倍率目标时保持原绑定并报错。

自动恢复只针对本机制保存了可靠恢复快照的降组账号。持续慢降组需所有已达慢请求门槛类别的恢复证据；异常降组保留降组前已观测的类别，无有效类别时以降组后第一个有效类别开始恢复。低倍率期间新发现的持续慢类别也会加入恢复要求。不同模型、短上下文不能替代原慢请求类别。

恢复期间出现上游失败或明确过载，会重置恢复样本；样本不足保持低倍率。恢复还要求账号满足现有调度条件，不能绕过限流、过载、过期或额度限制。恢复仅还原原高倍率组及优先级，撤销本机制临时添加的低倍率绑定，保留原有低倍率和其他平台绑定；任一原高倍率目标不可用时保留当前绑定并提示处理。

每次变组创建新统计轮次，变组前在途请求不能污染新样本。数据库账号行锁串行处理计数和决策，分组、恢复快照与调度 outbox 在同一事务提交，之后刷新调度快照。

## 人工修改与兼容

- 人工修改账号分组、批量改组或从分组侧添加绑定，会暂停该账号自动管理。普通编辑保留数据库中的最新自动分组状态，避免旧页面覆盖恢复快照。
- 账号状态提供“按当前分组恢复自动管理”：以当前人工绑定重新开始，放弃旧恢复目标，保留仍生效的变组保护。复用现有账号更新接口，发送 `extra.openai_auto_group_resume=true`；该一次性指令必须单独发送，后端只原子更新自动分组状态，不走通用配置替换，额度和其他账号配置完整保留。
- 新账号默认分组、显式指定分组、复制账号和影子账号原有规则保留。复制不继承来源账号的自动分组运行态，影子账号不参与自动升降组。
- 旧 `enabled` 仍表示异常自动降组。`window_minutes` 仅兼容旧客户端读写，不参与决策；缺少请求窗口时默认 20，旧异常阈值更大时窗口相应增大以保留有效配置。新增行为默认关闭。
- 保存设置生成新 revision，旧样本重新累计，旧请求不能写入新统计轮次；既有保护和恢复绑定保留。其他实例的启用缓存最多 5 秒更新，执行时再次核实设置 revision。
- 旧版本降组记录缺少可靠恢复快照时不自动升组。

## 状态与故障处理

账号状态显示判定原因、异常／慢请求样本数、恢复样本进度、类别和保护截止时间。恢复样本数达标仍须满足比例、中位数、连续快请求和健康条件。仅观察会显示建议，人工改组显示暂停。

失败保留绑定与恢复快照，账号列表顶部和账号行显示具体账号名称／ID、错误与处理入口。数据库不可用时可能无法持久化失败状态，需检查 `openai_auto_group_status_save_failed` 日志。成功变组日志为 `openai_auto_group_changed`，错误日志为 `openai_auto_group_failed`。

Redis 使用每账号一个有界记录，按请求数量裁剪，不因经过时间删除样本；Redis 数据丢失时保守重新累计。最多保留 32 个同类类别，每类至多配置要求的样本数，去重最多 4096 个请求标识。新类别超过容量会持续提示失败并阻止恢复，后续已知类别的快请求不能解除此阻断，不静默将缺失样本视为健康；检查模型配置后保存设置可重新开始。记录仅含请求标识与统计元数据，不含提示词和凭据。
